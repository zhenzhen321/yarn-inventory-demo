# 测试与验收

## 1. 测试策略

| 层级 | 工具/方式 | 覆盖内容 |
| --- | --- | --- |
| 自动化测试 | Vitest（26 个测试文件、155 个测试） | 金额精度、会话、独立批次、扫码标签、库存流水、加工血缘、结算、报表、撤回与删除保护 |

## 3. e2e 覆盖（`scripts/e2e.mjs`）

自包含、可重复运行：登录 → 建测试数据 → 买入（生成内部批次/二维码）→ 卖出批次分配 → 调拨 → 送加工 → 加工产出新批次 → 加工收回 → 盘库清零归档 → 结算与超结拦截 → 折让 → 撤回与反向流水 → 报表/日志页面渲染 → Excel 导出。

运行方式：

```bash
node scripts/e2e.mjs                     # 默认 localhost:3000
E2E_BASE_URL=http://localhost:3100 node scripts/e2e.mjs
node scripts/cleanup-e2e.js              # 清理带 E2E 前缀的测试数据
```

## 4. 验收标准

1. 克隆仓库后按 README 快速开始可一键跑通（建库 → 种子 → 启动 → 登录）。
2. 所有页面在桌面与手机宽度下可用。
3. 库存、结算、加工费金额计算与业务规则一致（单测覆盖）。
4. 错误路径有拦截（库存不足、重复扫码、并发修改、超结、未核算原料出厂、越权撤回）。
5. 相同供应商批号的不同采购保持独立内部批次，销售成本来自实际分配批次。
6. 加工成品可反查原料批次、投入成本、损耗和后续销售。
7. e2e 全部通过且测试数据可清理，不污染演示数据。

提交前可运行 `npm run check` 一次完成单元测试、类型检查和生产构建。
