# 服务器与域名部署演示

这套配置用于展示项目具备远程部署能力，不代表必须把真实业务系统部署到公网。准备一台 Linux 服务器和一个域名后，只需替换环境变量即可启动同样的演示站点。

## 部署结构

```text
访问者浏览器
    ↓ HTTPS（80/443）
Caddy：自动申请/续期证书、反向代理
    ↓ 容器内 3000 端口
Next.js 应用
    ↓
SQLite 持久化卷 + 独立备份卷
```

数据库与备份不写入容器临时层，因此重新构建应用容器不会丢失演示数据。此方案按单机、单应用实例设计。

## 准备条件

- 一台能运行 Docker Engine 与 Docker Compose 的 Linux 服务器
- 域名的 A/AAAA 记录已指向服务器公网 IP
- 云安全组和服务器防火墙已放行 TCP 80、TCP 443；HTTP/3 可额外放行 UDP 443
- 仓库代码已复制或克隆到服务器

## 首次启动

在项目根目录执行：

```bash
cp .env.production.example .env.production
```

编辑 `.env.production`，至少替换：

- `DOMAIN`：实际演示域名，例如 `inventory-demo.example.com`
- `SESSION_SECRET`：至少 48 位随机字符串
- `ADMIN1_PASSWORD`、`ADMIN2_PASSWORD`：公网演示账号的强密码

然后启动：

```bash
docker compose up -d --build
docker compose ps
```

首次启动会执行数据库迁移并写入演示数据；以后重启不会再次清空数据库。Caddy 会在 DNS 与端口正确时自动配置 HTTPS。

## 验证

```bash
curl https://inventory-demo.example.com/api/health
docker compose logs --tail=100 app
docker compose logs --tail=100 caddy
```

健康接口正常时返回：

```json
{"status":"ok"}
```

再用浏览器打开域名，使用 `.env.production` 中设置的账号密码登录并检查关键业务页面。

## 日常操作

查看运行日志：

```bash
docker compose logs -f app
```

手动备份数据库：

```bash
docker compose exec app npm run backup
```

拉取代码更新后重新构建：

```bash
docker compose pull
docker compose up -d --build
```

停止服务但保留数据：

```bash
docker compose down
```

> `docker compose down -v` 会删除演示数据库、备份和 Caddy 数据卷，仅适合明确需要彻底重置演示环境时使用。

## 边界说明

- 当前 SQLite 配置适合单机、低到中等流量的功能展示，不应横向启动多个应用副本。
- 正式业务上线前应进一步评估 PostgreSQL 等数据库、对象存储备份、日志与监控、最小权限、限流/WAF 和隐私合规。
- 不要把 `.env.production`、数据库文件或备份提交到 GitHub。
