# 纱线进销存管理系统 · 需求与目标

| 项目 | 内容 |
| --- | --- |
| 文档用途 | 明确系统要做什么、做到什么程度，评审确认后再开发 |
| 状态 | 确认版 v1.1（批次溯源与扫码出库） |
| 评审人 | 需求方 |

## 1. 项目背景

纱线贸易经营场景：公司有多个仓库，存放多种纱线（不同原料、支数、色号、批次）。此前进出货、库存和资金结算依赖人工记录与记忆，容易出现账实不符、结算遗漏等问题。需要一套专为纱线业务设计的进销存管理系统。

## 2. 项目目标

1. 每一笔买入/卖出都有完整记录（纱线、重量、单价、总价、对方、仓库、经办人、日期）。
2. 库存实时准确：每笔出入库自动增减库存，支持多仓库，随时可查。
3. 资金结算进度可跟踪：应收应付清晰，未结/部分/已结一目了然。
4. 安全可控：密码登录、操作留痕、数据备份，账目不能随意改、删。
5. 数据可导出（Excel），长期可扩展（后续加功能不推倒重来）。
6. 货物可按独立内部批次追溯采购、位置、加工、销售与冲销全过程。
7. 通过批次二维码和键盘式扫码枪降低出库选货成本，同时保留提交时的库存校验。

## 3. 范围

### 3.1 范围内

- 纱线档案、仓库、供应商/客户管理
- 买入入库、卖出出库、仓库间调拨、盘库
- 库存实时查询与报表
- 资金结算跟踪（应收/应付、结算登记、对账）
- 加工费流程（送加工、加工费结算、加工收回、工厂欠款）
- 独立货源批次、分地点余额、不可变库存流水和加工父子批次
- 一批一码的二维码标签、打印预览和扫码出库
- 用户登录、操作日志、数据备份

### 3.2 范围外（第一版不做）

- 生产排产、染色配方、机台和工序级生产管理
- 财务总账、报税、工资
- 合同电子签章、发票管理

## 4. 用户与角色

| 角色 | 权限 |
| --- | --- |
| 管理员 | 全部功能：录入、改档案、结算、冲销、看报表 |
| 仓管 | 与管理员一致（第一版不细分权限，保留 role 字段以便将来扩展） |

## 5. 核心功能需求

- **F1 登录与安全**：密码登录、JWT 会话、登录限速、CSRF 校验、所有写操作留痕。
- **F2 纱线档案**：产品（名称）+ 变体（支数/色号/单位）两级模型，支持搜索。
- **F3 仓库管理**：维护仓库列表（名称、地址、负责人），支持普通仓库与加工厂两种类型。
- **F4 往来单位**：供应商、客户统一管理，一个单位可以既是供应商又是客户。
- **F5 买入入库**：自动单号、日期、供应商、仓库、明细（纱线/批次/重量/单价），保存后库存自动增加，重量必填、包数选填。
- **F6 卖出出库**：自动单号、客户、明细；保存前校验库存是否足够，不足则拦截；保存后库存自动减少。
- **F7 仓库调拨**：A 仓调货到 B 仓，只改变库存分布；支持送加工（记录运费）。
- **F8 库存查询**：按仓库、纱线、批次、色号组合筛选，含批次与重量。
- **F9 资金结算**：按往来单位汇总应收应付，支持未结/部分/已结、多笔结算登记、超结拦截；支持折让。
- **F10 盘库**：录入实盘数，自动计算盘盈/盘亏，支持盘点周期提醒。
- **F11 报表**：库存金额（按实际内部批次成本）、毛利估算、客户/供应商订单查询、近 30 天流水，可导出 Excel。
- **F12 加工费**：加工完工时记录投入/产出、损耗和加工费并生成成品批次；已核算成品可回仓或直销，加工费付款状态不阻止成品出库。
- **F13 冲销与撤回**：录错的单据不直接删除，支持带权限校验的撤回，库存与结算联动回滚，全部留痕。
- **F14 批次溯源**：每条采购明细形成唯一内部批次，按地点保存余额，以追加式流水记录采购、调拨、加工、销售、盘点和冲销。
- **F15 扫码标签**：内部批次生成不可猜测扫码令牌；标签显示批次、品名、规格、重量和件数；销售表单支持扫码枪回车选货。
- **F16 加工血缘**：加工投入保留原料批次，产出始终建立新成品批次，可查询父子关系、损耗、成本和后续去向。

## 6. 关键决策记录

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 第一版用 SQLite，Prisma Migrations 管理结构 | 部署简单、单机使用足够；schema 变更可追溯 |
| D2 | 结算按往来单位汇总，而非按单结算 | 业务习惯是按对方结款，部分结算时对账更直观 |
| D3 | 加工完工核算与付款分离 | 完工即固化投入、产出、损耗、成品成本和加工厂应付；付款只冲减应付 |
| D4 | 运费不计入应收应付，但计入成本与毛利 | 业务上运费由己方承担，单独记录便于毛利核算 |
| D5 | 测试数据必须带前缀并可定向清理，严禁全库重置 | 保护真实业务数据 |
| D6 | 供应商批号与内部批次分离 | 外部批号可重复；内部批次才是唯一成本和追溯身份 |
| D7 | 二维码只保存随机扫描令牌 | 快速定位批次，同时不向标签暴露采购成本 |
| D8 | 重量为权威数量、件数为整数辅助数量 | 成本按重量核算，件数用于标签、现场识别和盘点 |
| D9 | 已被下游使用的记录通过反向流水冲销 | 保留来源链，避免物理删除破坏审计与追溯 |

## 7. 遗留/后续方向

- 更细粒度的角色权限（仓管/财务分离）
- 单据拍照上传、微信小程序
- PostgreSQL 部署与在线演示

## 8. 近期公开 Demo 增量需求

- 写操作应支持幂等请求标识：网络重试或重复点击不得重复创建单据、库存流水或审计记录；相同标识但请求内容不同必须拒绝。
- 加工完工应支持多个投入批次和多个成品批次；投入必须来自同一加工厂，货物成本、运费、加工费和其他费用按成品分配权重计算，并保留尾差归属。
- 常用演示场景提供点选快捷项、大字模式、业务日期快捷选择、保存中锁定和未保存提醒，但不改变服务端库存与成本规则。
