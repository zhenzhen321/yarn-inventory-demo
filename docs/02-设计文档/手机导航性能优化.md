# 手机导航性能优化

状态：已同步到公开 Demo；生产发布信息不纳入 Demo。用户已同意诊断、减轻页面取数与基础资料短期缓存，明确不增加导航等待提示。

## 已确认范围

- Demo 使用标准 `next start`；网络延迟与设备性能会影响实际体验，本文指标仅用于说明测量方法。
- 首页使用聚合与必要字段查询；库存以整组来源单据进行数据库分页，加工数据展开时加载；卖出按仓取库存并通过专用接口跨仓查码。
- 只缓存启用仓库、往来单位和采购品种选项（30秒）；基础资料写入、采购/加工自动创建规格后使缓存失效。库存、资金余额与鉴权不缓存。
- 不升级依赖、不迁移数据库、不改业务写事务、金额分摊、扫码确认/去重及未保存提醒规则。

## 基准与验收

假设：减少无关数据和客户端代码可降低业务页切换等待；当前直连情况下是否有明显收益以实测为准。

实测发现额外原因：本机响应已返回，新内容仍约300ms后显示，与React的fallback throttle相符。最终去掉统一 `app/app/loading.tsx`，保留当前页面直到新页准备好，避免快速请求也经历骨架切换；未增加导航提示或修改框架依赖。

源项目发布验收曾使用内部只读导航测量工具（绑定本机浏览器），该工具和运行依赖不包含在公开 Demo 中。公开 Demo 改用单测、HTTP E2E 和人工响应式检查；性能体验仍受设备与网络影响，不作任意环境下的数值承诺。

通过条件：类型检查、全套单测、隔离业务E2E与手机浏览器验收；新旧汇总/分页对等，异步换仓/扫码无串单或重复加入，主数据修改后新请求立即可见；无导航提示新增，无真实业务写入。性能报告提供实际变化，不承诺任意网络下秒开。

验证使用 `.next-build` 和非3000端口；不覆盖在线 `.next`。发布如执行，按交接说明先备份、保存回滚构建并记录生产只读核对。
