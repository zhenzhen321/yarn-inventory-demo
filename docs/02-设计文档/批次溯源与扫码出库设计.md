# 批次溯源、二维码出库与加工血缘设计

> 状态：已实现。本文描述公开 Demo 的当前模型、业务规则和验收边界。

## 1. 目标

- 每条采购明细形成独立内部批次，保留真实采购成本。
- 一批一码、一批一张标签，二维码不暴露采购成本。
- 销售可按“仓库 → 品名 → 色号 → 内部批次”选择，也可扫码快速定位。
- 库存变化以追加式流水记录，可从采购追到调拨、加工、销售、盘点和冲销。
- 加工投入与产出建立父子批次，固化重量差异、加工费和成品成本。

## 2. 核心模型

~~~text
PurchaseItem ──→ InventoryLot ──→ Inventory（分地点余额）
                       │
                       ├── StockMovement（不可变库存流水）
                       ├── SaleAllocation ──→ SaleItem
                       └── ProcessingInput ──→ ProcessingJob
                                                  │
                                                  └── ProcessingOutput ──→ 新 InventoryLot
~~~

### InventoryLot

货物稳定的来源和成本身份，保存：

- 唯一内部批次号 `lotNo`
- 随机扫码令牌 `scanCode`
- 来源类型：采购、加工产出或历史汇总
- 品种、规格/色号、供应商批号
- 初始重量/件数、货物成本、运费、加工成本
- 当前状态与来源质量

供应商批号允许重复；内部批次号和扫码令牌全局唯一。同一品种、同一供应商批号在不同采购明细中不会合并。

### Inventory

作为“内部批次 + 地点 + 加工状态”的当前余额，保存重量、件数、成本、运费和版本号。同一内部批次部分调拨后可以同时存在于多个地点。

### StockMovement

只追加、不覆盖的库存流水，类型包括采购入库、调拨、加工消耗、加工产出、销售、盘点和冲销。每条流水保存来源/目标地点、重量、件数、成本快照和业务单据引用。

### SaleAllocation

连接销售明细与实际内部批次，保存发货地点、重量、件数及销售发生时的单位成本/运费快照。毛利来自实际批次，不使用全局平均成本。

### ProcessingJob / Input / Output

加工任务关联投入原料批次与产出成品批次。完工时一次性记录投入、实际产出、损耗、加工费和成本分配；加工产出始终创建新的内部批次。

## 3. 二维码设计

- 二维码内容仅为随机 `scanCode`，不写入成本、客户、供应商或数据库主键。
- 标签显示单号、品名、规格、色号、供应商批号、重量、件数和内部批次号。
- 二维码由浏览器本地生成，不依赖外部二维码服务。
- 支持 USB HID 键盘模式的二维扫码枪，建议配置“扫码后发送 Enter”。
- 销售扫码框也接受 `lotNo`，方便没有硬件时演示相同选货路径。

扫码只把批次加入销售草稿。正式提交仍在服务端事务中重新校验地点、加工状态、库存余额和版本号。

## 4. 业务规则

1. 重量是库存和成本核算的权威数量，件数是整数辅助数量。
2. 整批出库默认带出全部余额与件数；部分出库在原库存有件数时必须明确填写本次件数。
3. 调拨只改变地点余额，不改变内部批次来源；本次运费进入移动后余额成本。
4. 未完成加工核算的染厂原料不能卖出或调出。
5. 已完成核算的成品即使加工费尚未付款，也能回仓或从染厂直接销售。
6. 加工损耗通过实际产出重量提高成品单位成本，不凭空减少投入成本。
7. 被下游使用的采购/销售记录不物理删除；撤回写入反向流水并保留原单。
8. 并发扣减使用余额版本号，更新失败时提示刷新，防止重复出库。

## 5. 典型追溯链

~~~text
采购单
  → 原料内部批次
  → 仓库余额
  → 送厂流水
  → 加工消耗
  → 加工任务（投入、产出、损耗、加工费）
  → 成品内部批次
  → 回仓或染厂直销
  → 销售批次分配
~~~

批次追溯页集中展示采购来源、父批次/子批次、当前位置、全部库存流水和销售客户。

## 6. Demo 数据

种子数据刻意包含：

- 两次日期、价格不同但供应商批号同为 `C20260801` 的采购，用于证明内部批次不会合并。
- 一个原料批次部分销售、部分调拨到另一仓库。
- 一个原料批次送加工厂、完工产生新成品批次、部分返仓并形成加工费应付。
- 销售批次分配、盘点流水和资金结算。

## 7. 已知边界

- 当前界面以一条销售行选择一个内部批次；一张销售单可添加多行实现一单多批。
- 当前完工界面主要展示单投入、单产出；底层模型允许多个投入/产出，复杂拼缸/拆缸需要专用交互和成本分配规则。
- 真实扫码枪、打印机和标签纸需要在实际设备上校准，自动化测试只覆盖软件行为。
- SQLite 部署按单机、单应用实例设计，不做多副本横向扩容。

## 8. 验收重点

- 同品种、同供应商批号、不同日期/价格采购保持独立。
- 整批扫码、部分销售、重复扫码、库存不足和并发提交。
- 部分调拨后同一批次在多个地点的余额与总量。
- 加工投入、产出、损耗、成本、加工费应付和父子血缘。
- 加工费未付款时已核算成品仍可出库。
- 撤回后原单保留，并生成精确反向流水。
