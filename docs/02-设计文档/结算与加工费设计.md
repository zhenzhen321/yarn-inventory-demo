# 结算与加工费设计

> 对应需求：F9、F12。本文档定义资金结算与加工费结算的数据模型与规则。

## 1. 目标

- 每个供应商/客户的应收应付一眼可见：未结、部分结算、已结。
- 结算多笔可叠加，不允许超结。
- 加工费按库存行结算，自动生成工厂欠款，付款后实时更新余额。

## 2. 核心数据模型

```
Counterparty（往来单位）
  ├─ PurchaseOrder（应付总额）
  ├─ SaleOrder（应收总额）
  └─ Settlement（结算记录：方向/金额/日期/方式/经办人）

Warehouse(type=FACTORY)
  ├─ Inventory（加工费状态 processingFeeSettled / processingFeePerKg）
  ├─ ProcessingFeeSettlement（加工费结算明细：投入/产出/单价/总额/新成本）
  └─ ProcessingFeePayment（工厂付款记录）
```

## 3. 业务规则

| 规则 | 说明 |
| --- | --- |
| 汇总口径 | 应付=该供应商全部买入单 totalAmount 之和；应收=该客户全部卖出单 totalAmount 之和 |
| 结算进度 | 已结金额 >= 总额 → 已结；已结金额 > 0 → 部分结算；否则未结 |
| 超结拦截 | 结算金额超过未结金额时拒绝，并返回当前未结金额 |
| 折让 | 方式为「折让」的 SALE 结算单独聚合，在往来单位页展示折让总额与明细 |
| 加工费按行结算 | 只允许加工厂库存；结算时录入加工单价、投入重量、产出重量，可变更支数/色号/批次 |
| 成本结转 | 加工后新行成本 = 投入部分原成本 + 加工费总额；新单位成本随之更新 |
| 工厂欠款 | 欠款 = 全部加工费结算 feeTotal 之和 − 全部付款之和；超付拦截 |
| 出库约束 | 加工厂库存未结算时，卖出/调拨/加工收回全部拒绝 |

## 4. 关键计算示例

- 买入 800kg @18.8，运费 200 → 库存行 cost=15040、freight=200。
- 送加工 150kg（运费 50）→ 目标行 cost=2820、freight=87.5。
- 加工费 2 元/kg，投入 150kg 产出 140kg → feeTotal=280，新行 cost=3100，单位成本=22.14。
- 工厂付款 100 → 欠款 = 280 − 100 = 180。

## 5. 待确认点与决策

| # | 问题 | 决策 |
| --- | --- | --- |
| Q1 | 按单结算还是按往来单位结算？ | 按往来单位汇总，符合实际对账习惯 |
| Q2 | 加工费算在货款里吗？ | 独立结算，单独形成工厂欠款，便于与加工厂对账 |
| Q3 | 部分加工后剩余白坯怎么处理？ | 剩余库存保持未结算状态，可再次结算或留作他用 |
| Q4 | 结算错了怎么办？ | 仅经办人可撤回，撤回后应收应付自动回滚并留痕 |
